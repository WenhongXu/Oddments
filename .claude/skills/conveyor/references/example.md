# Conveyor 完整走查示例：客户资料批量分析

一个从头到尾的示范，演示五个阶段、两种异常、一次中断恢复和最终打包。
阅读本例可以校准"每一步做到什么程度算合格"。

---

## 场景

用户说：

> `./客户资料/` 下每个客户一个文件夹，里面有基本信息和交易流水，
> 帮我逐个分析风险并打分，每个客户出一份报告，放到 `./客户分析结果/`。

目录实况：

```
客户资料/
├── C0012_张三公司/（基本信息.md、交易流水.xlsx）
├── C0013_李四商贸/（基本信息.md、交易流水.xlsx）
├── C0015_王五实业/（基本信息.md）            ← 缺流水
├── C0016_赵六贸易/（基本信息.md、交易流水.xlsx）
└── C0019_孙八科技/（基本信息.md、交易流水.xlsx、诉讼记录.pdf）← 多一个文件
```

---

## 阶段 0 — 理解任务

从提示词已能确定：循环项=客户、清单来源=目录扫描、输入=两个文件、
输出位置=./客户分析结果/。仍缺的要素**一次问齐**：

> 开始前确认四件事：
> 1. 评分标准是什么？（如 1~5 分，依据哪些因素）
> 2. 报告需要哪些章节？
> 3. 如果某个客户缺关键文件（比如没有流水），是跳过还是只做定性分析？
> 4. 最后要不要把所有报告打包成一个 zip 给您？

用户答：按流水规模和异常交易打 1~5 分；章节要【基本情况/风险点/评分/依据】；
缺流水就只做定性、标注清楚；要打包。

→ 将全部要素写入 `_批量控制/01_任务计划.md`（草稿）。

## 阶段 1 — 试跑 C0012

按顺序读 `基本信息.md` → `交易流水.xlsx`，产出
`交付/C0012_张三公司/C0012_分析报告.md`（文件头带元信息），
把报告和整理出的 SOP 摘要给用户看。用户说"风险点再细一点"→ 修订 SOP、
重做 C0012 → 用户确认 → SOP 定稿为 v1，写入任务计划。

## 阶段 2 — 建清单

扫描目录得 5 项，校验 ID 无重复，写入 `02_状态清单.md`：

| 序号 | ID | 名称 | 输入位置 | 状态 | 完成时间 | 备注 |
|---|---|---|---|---|---|---|
| 1 | C0012 | 张三公司 | 客户资料/C0012_张三公司/ | 已完成 | 07-08 10:32 | 试跑样例 |
| 2 | C0013 | 李四商贸 | 客户资料/C0013_李四商贸/ | 待处理 | | |
| 3 | C0015 | 王五实业 | 客户资料/C0015_王五实业/ | 待处理 | | |
| 4 | C0016 | 赵六贸易 | 客户资料/C0016_赵六贸易/ | 待处理 | | |
| 5 | C0019 | 孙八科技 | 客户资料/C0019_孙八科技/ | 待处理 | | |

向用户汇报："共 5 个客户，C0012 已随试跑完成，按序号继续处理剩余 4 个。"

## 阶段 3 — 逐项循环

### 回合 1：C0013（一切正常）

1. 重读清单 → 第一个待处理是 C0013 → 标"处理中"，保存
2. 列目录：两个文件都在，与预期一致（同构）
3. 按 SOP v1 顺序处理，写 `交付/C0013_李四商贸/C0013_分析报告.md`
4. 自检：文件头 ID = 目录 ID = 清单 ID ✓；四个章节齐 ✓
5. 清单标"已完成"+时间，保存
6. 汇报一行：`[2/5] C0013 李四商贸 已完成`

### 回合 2：C0015（异常②——缺关键输入）

列目录发现没有 `交易流水.xlsx`。按阶段 0 约定的异常边界：只做定性、不打分。

- 产出报告（无评分节，开头显著标注"缺交易流水，未评分"）
- **当场**追加异常记录：`C0015 | 缺交易流水.xlsx | 只做定性 | ②部分完成 | 报告无评分`
- 清单标"部分完成"，备注"缺流水"
- 汇报：`[3/5] C0015 王五实业 部分完成（缺流水，已记录异常）`

### （中断演示）上下文被压缩 / 会话重开

恢复动作固定三步：读 `01_任务计划.md` 恢复 SOP → 读 `02_状态清单.md`
发现 C0016 卡在"处理中"→ 其交付目录是半成品，清空重做，
异常记录追加一条"C0016 中断重做"。**不凭记忆猜进度。**

### 回合 3：C0016（重做后正常完成）

同回合 1。汇报：`[4/5] C0016 赵六贸易 已完成（中断后重做）`

### 回合 4：C0019（异常①——多出预期外文件）

列目录多出 `诉讼记录.pdf`。能确认归属（就在该客户目录内）、读取无风险
→ 属"①可自行处理"：读取后在报告增加"附注"节引用其内容。

- 异常记录追加：`C0019 | 多出诉讼记录.pdf | 已读取并附注 | ①自行处理 | 报告多一节`
- 汇报：`[5/5] C0019 孙八科技 已完成（多一份诉讼记录，已附注并记录异常）`

> 反例对照：如果多出的文件叫 `C0021_流水.xlsx`（ID 对不上），
> 就**不能**并入 C0019——那是"归属不明"，应按②记录后不使用，
> 必要时升③询问用户。

## 阶段 4 — 核对、汇总、打包

1. 清单 5 行全部到达终态 ✓
2. 逐行核查：4 个"已完成"目录及报告齐全、文件头 ID 一致；
   C0015"部分完成"符合记录 ✓
3. 生成 `04_汇总报告.md`：5 项 = 完成 4 + 部分完成 1；异常 3 条摘要；
   交付物索引全量列出
4. 打包：`zip -r 客户分析_交付_20260708.zip 交付/ _批量控制/04_汇总报告.md`
   → 校验 zip 存在、条目覆盖全部已完成项
5. 向用户交付：

> 全部 5 个客户处理完毕：4 个完成、1 个部分完成（C0015 缺流水，未评分）。
> 汇总报告：`客户分析结果/_批量控制/04_汇总报告.md`
> 打包文件：`客户分析_交付_20260708.zip`
> 待跟进：C0015 补充流水后可单独重做该项。

---

## 变体速查

- **页面交付**：SOP 产出改为 `<ID>_报告.html`，图表等资源放在同一
  `<ID>_<短名>/` 目录内、相对路径引用；阶段 4 照常打包，解压即可打开。
- **输入来自查询而非文件**：每回合先把查询结果原文存为该项目录下的
  `输入快照_<来源>.md`，再基于快照处理。
- **清单来自用户口述**：用户报一个处理一个时，同样先把该项追加进清单
  （来源标"用户提供"）再开回合，收到"没有了"后按阶段 4 收尾。
- **无文件系统平台**：用消息内清单快照（见 templates.md 第 7 节）维持
  同样的回合纪律；zip 打包不可用时在最终汇报中注明。
